Hi everyone, I’m Abhishek Raghuwanshi, an Engineering Sciences student at IISER Bhopal. This is my video submission for the Induseuro Labs LLM Agent Engineering Internship assignment. [Show GitHub repo page: https://github.com/9905abhishek-stack/intern-assignment-llm-cost-optimization]

The assignment consists of two specific optimization challenges:
* Question 1: Resolve tickets using a single LLM call, bringing inference costs down to under 3,000 points per ticket. [questions/question-1.md: line 18]
* Question 2: Optimize a multi-node pipeline against a massive 200,000-token knowledge base, bringing costs down to under 2,500 points per ticket. [questions/question-2.md: line 9]

Let's look at the major changes made to solve both questions.

In Question 1 (question1/agent.py), the unoptimized baseline had two major flaws: it placed a random UUID on line 1 which completely broke prompt caching, and it used trigger phrases like 'think step by step' which forced the model into an expensive 480-token output trap.
To fix this, I made two major changes:
First, I removed the random UUID so the system prompt remains identical across requests, enabling prompt caching. [question1/agent.py: lines 62-67]
Second, I removed the verbosity trigger words and instructed the model to output clean JSON directly. This shrunk output tokens from over 480 down to around 40 tokens—saving thousands of points per call. [question1/agent.py: line 68]

In Question 2 (question2/agent.py), the baseline was burning over 70,000 points per ticket because it stuffed over 120,000 tokens of raw knowledge base text directly into the prompt.
To fix this, I replaced context stuffing with selective retrieval:
First, in Triage, we pass only a lightweight 30-token article titles index instead of the raw text. [question2/agent.py: line 44]
Second, in Retrieve, Python directly loads only the single matched article file—consuming zero LLM tokens. [question2/agent.py: lines 56-58]
Third, in Audit, if the composed JSON is already valid, it short-circuits without making an unnecessary second LLM call. [question2/agent.py: lines 92-97]

Looking at my GitHub README, here are the verified results: [README.md: lines 14-18]
* In Question 1, all public tickets resolve with 100% accuracy, averaging 1,972 points per ticket—well below the 3,000-point ceiling. [README.md: lines 27-31]
* In Question 2, all tickets pass with 100% accuracy, averaging 2,113 points per ticket—comfortably beating our 2,500-point limit. [README.md: lines 41-44]

All changes are committed and pushed to my repository. Thank you for your time, and I look forward to hearing from the team! [Show top of GitHub repository page]
