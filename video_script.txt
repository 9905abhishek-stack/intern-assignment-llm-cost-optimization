Question 2: Optimize a multi-node pipeline against a massive 200,000-token knowledge base, bringing costs down to under 2,500 points per ticket.

Let's look at the major changes made to solve both questions.

In Question 1 (question1/agent.py), the unoptimized baseline had two major flaws: it placed a random UUID on line 1 which completely broke prompt caching, and it used trigger phrases like 'think step by step' which forced the model into an expensive 480-token output trap.
To fix this, I made two major changes:

[GO TO: question1/agent.py -> Lines 62-67]
First, I removed the random UUID so the system prompt remains identical across requests, enabling prompt caching.

[GO TO: question1/agent.py -> Line 68]
Second, I removed the verbosity trigger words and instructed the model to output clean JSON directly. This shrunk output tokens from over 480 down to around 40 tokens—saving thousands of points per call.

In Question 2 (question2/agent.py), the baseline was burning over 70,000 points per ticket because it stuffed over 120,000 tokens of raw knowledge base text directly into the prompt.
To fix this, I replaced context stuffing with selective retrieval:

[GO TO: question2/agent.py -> Line 44]
First, in Triage, we pass only a lightweight 30-token article titles index instead of the raw text.

[GO TO: question2/agent.py -> Lines 56-58]
Second, in Retrieve, Python directly loads only the single matched article file—consuming zero LLM tokens.

[GO TO: question2/agent.py -> Lines 92-97]
Third, in Audit, if the composed JSON is already valid, it short-circuits without making an unnecessary second LLM call.
